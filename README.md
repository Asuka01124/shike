# 拾刻

Windows 奖励定时领取工具。登录B站一次，添加奖励并选好时间，到点自动领取；结果保存在“领取记录”中。采用 Rust + GPUI 原生界面。

## 使用

1. 运行 `拾刻.exe`，点击“登录B站”，在打开的官方网页完成登录。软件会记住登录状态。
2. 点击“添加奖励”，粘贴具体奖励的领取页面链接。
3. 选择“明天零点”“现在领取”或“自选时间”。所有时间均为北京时间。先登录，再添加奖励；每份奖励会记住所属账号，账号名称显示在领取时间旁。
4. 到点后会自动领取，成功后进入“领取记录”。有兑换码时可以直接复制，也可以打开领取页查看。
5. “退出登录”会停止该账号后续的自动领取，保留领取安排和记录。重新登录同一账号后，未到期的安排自动恢复；已错过的时间需要重新安排，手动暂停的奖励保持暂停。
6. 不同账号的奖励在同一列表中展示。仅当前登录账号的奖励会自动领取，其他账号的奖励显示“等待登录该账号”。退出时已提交的领取会继续记录返回结果，归属原账号。
7. 关闭窗口后仍会继续等待。双击系统托盘中的拾刻图标可重新打开；要结束程序，请在系统托盘中右键选择“退出软件”。

请复制某个具体奖励的领取页面地址，活动海报首页不能用于领取。同一账号下同一份奖励只需添加一次，已领取的奖励不会重复执行。切换账号不会改变已有奖励的归属。

程序需在运行状态、电脑开机且有网络时执行。等待任务时会请求系统保持唤醒，但手动休眠、合盖或关机会中断。未设置开机自启动。重启程序后会恢复尚未到期的任务；明显错过时间的任务可编辑时间后继续。

## 本地文件

所有数据保存在程序同目录的 `data/`：

- `tasks.json`：账号会话、任务和归档结果。
- `tasks.backup.json`：上一次保存的副本。
- `browser-profile/`：独立登录浏览器配置。

Cookie本地保存，不依赖Node.js、Python或远程应用服务器。登录浏览器优先使用本机Chrome，找不到时使用Edge。登录态失效时点击“重新登录”。

准备奖励信息时遇到明确限流，显示“等待恢复”，保留原领取时间并稍后自动继续。关闭再打开软件也会保留冷却时间。登录失效、网页验证或资格错误会显示原因，需要处理后再安排。

领取接口仍由B站判定资格、库存和验证要求。正式领取请求遇到验证码或明确限流会停止该任务；领取请求网络超时会保留为未完成，便于核对领奖记录。不会自动解决验证码。

## 准备与恢复

同一登录会话的任务共享登录验证和签名缓存，准备操作依次执行，信息读取请求至少间隔一秒。成功读取的奖励信息在本地保留5分钟，短时间内重启可复用；过期或更换链接时重新读取，仍须验证账号归属。读取接口返回 HTTP 429、业务码 -702 或 -509 时，依次冷却30秒、60秒、120秒，之后维持120秒；若服务端的 `Retry-After` 更长则按服务端时间等待。冷却截止时间和准备失败次数写入本地任务文件，重启不会立即重试。

每个准备阶段连续受限最多6次，最晚不超过原领取时间后60秒；仍未准备好则显示待处理，保留原定时间供重新安排。暂停、退出登录不会重置尚未结束的冷却；新账号不会使用旧账号的任务。旧版零次领取且明确因准备限流失败的未来任务会迁移为等待恢复，已提交领取后停止的任务保持原结果。

到点领取仍采用两条工作线程，每条最多每秒一次。准备流程的自动恢复只处理读取接口的明确限流，正式领取的风控停止规则保持不变。

## 构建

需要Rust 2024工具链、Visual Studio C++构建工具和Windows SDK（包含 `fxc.exe`）。当前环境可执行：

```powershell
.\build.cmd build --release
.\build.cmd test --lib --no-default-features --target-dir target-tests
```

其他环境可在VS开发者终端运行 `cargo build --release --locked`；必要时将 `GPUI_FXC_PATH` 指向SDK中的 `fxc.exe`。

`--demo` 只显示带示例任务的界面，不加载真实账号执行任务；`--probe` 只请求匿名任务信息并写入 `rust-api-probe.json`。
